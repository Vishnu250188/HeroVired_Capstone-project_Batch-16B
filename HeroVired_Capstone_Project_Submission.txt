1. PROJECT OVERVIEW

This project demonstrates the design and implementation of an end-to-end DevOps workflow for a containerized web application deployed on Kubernetes using Amazon Elastic Kubernetes Service (Amazon EKS).

The solution brings together application development, source-code management, automated testing, containerization, infrastructure as code, configuration management, continuous integration and continuous deployment, monitoring, and documentation.

Jenkins is used as the CI/CD orchestrator. Docker is used to package the application into a container image, and Amazon Elastic Container Registry (Amazon ECR) is used as the container image repository. Terraform is used to define and provision AWS infrastructure. Ansible is used for configuration-management tasks where applicable. Kubernetes manifests are used to define application deployment, service exposure, health checks, and scaling. Prometheus and Grafana provide monitoring and visualization where configured.

The project follows the supplied capstone requirements and is organized into six implementation sprints.

2. PROBLEM STATEMENT

DevOps teams need a reliable and repeatable way to build, test, package, and deploy applications. Manual deployment activities can introduce errors, slow down releases, and make environments difficult to reproduce.

This project addresses that challenge by designing a CI/CD workflow in which source-code changes can trigger automated validation and application delivery. Infrastructure is defined as code, application components are packaged as containers, and Kubernetes provides the deployment and orchestration platform on AWS.

The intended outcome is a documented and repeatable pipeline that reduces manual effort, improves consistency, and provides visibility into application and infrastructure health.

3. PROJECT OBJECTIVES

The objectives of the project are:

1. Design an AWS-based application architecture incorporating networking, container orchestration, load balancing, and monitoring.
2. Use Terraform to define AWS infrastructure, including a VPC, public and private subnets, IAM roles, Amazon ECR, and Amazon EKS.

5. Deploy the application to Kubernetes on Amazon EKS using Kubernetes manifests.
6. Use Jenkins to orchestrate build, test, image publishing, infrastructure, configuration, and deployment activities as implemented in the pipeline.
7. Configure health checks, scaling, monitoring, and notifications where included in the implementation.
8. Perform validation and document the implementation, test results, evidence, and operational steps.

7. CI/CD PIPELINE STAGES

The intended Jenkins pipeline consists of the following stages:

1. Source Checkout
   - Retrieve application source code from the GitHub repository.
   - Use the configured branch and repository credentials or access method.

2. Build and Dependency Installation
   - Prepare the build environment.
   - Install the application dependencies.

3. Automated Testing
   - Execute the application test suite.
   - Stop the pipeline if required tests fail.

4. Docker Image Build
   - Build the container image using the application Dockerfile.
   - Apply an appropriate image tag.

5. Image Publishing
   - Authenticate to Amazon ECR.
   - Push the successfully built image to the configured ECR repository.

6. Infrastructure Provisioning
   - Run Terraform initialization, validation, planning, and approved provisioning operations.
   - Store Terraform state remotely in Amazon S3.

7. Configuration Management
   - Run the required Ansible playbooks against the configured target systems.

8. Kubernetes Deployment
   - Configure access to the EKS cluster.
   - Apply Kubernetes manifests.
   - Wait for the deployment rollout and check workload status.

9. Post-Deployment Validation
   - Check Kubernetes resources and application health.
   - Report pipeline success or failure.

10. Monitoring and Notification
    - Review the configured Prometheus and Grafana monitoring.
    - Send notifications for configured pipeline or monitoring events.

Note: The final Jenkinsfile may combine, omit, or order some stages differently. The submitted description must reflect the actual Jenkinsfile and build logs.

9. SECURITY AND COST OPTIMIZATION

Security practices:
- Use IAM roles and policies with only the permissions required for each task.
- Avoid hardcoding AWS access keys or passwords in source code and Jenkinsfiles.
- Store credentials in the approved Jenkins credentials mechanism.
- Restrict public access to the Kubernetes API endpoint to approved IP addresses.
- Keep Terraform state in a protected S3 bucket with encryption and versioning.
- Do not commit Terraform state, plan files, private keys, or secret files to GitHub.
- Use container image scanning and dependency checks where configured.
- Use health checks and controlled deployment procedures.

Cost optimization:
- Select suitable EC2 instance types and node counts for the learning workload.
- Avoid leaving EKS clusters, EC2 instances, NAT Gateways, load balancers, and other billable resources running when not required.
- Use an appropriate ECR lifecycle policy to remove old images.
- Review AWS Cost Explorer and AWS Pricing Calculator estimates.
- Monitor storage, data transfer, NAT Gateway usage, and load-balancer charges.
- Destroy temporary resources after testing when they are no longer required, while preserving any resources needed for demonstration or evaluation.
